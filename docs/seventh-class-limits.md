# Seventh class: where the game assumes six

> Planning notes kept for their findings. Since they were written, extra classes became working (up to 127, paged on character select; see README.md "Extra classes"), so some "not possible yet" lines are out of date.

Written 2026-11-04 from a full disassembly of `game_unpacked.exe` (`dumpbin /disasm`, VS 2019 build tools) plus the data. Addresses are virtual addresses in the unpacked exe. It's a map, not a plan: each item says what the game does, what a seventh class would hit, and roughly what fixing it takes.

## Goal (agreed 2026-11-04)

**Many extra classes, not one.** Aim for roughly double (about 12), with no design choice that caps it at seven. Several custom classes must work **at the same time** (e.g. a four-player online party of custom classes).

Design rules that follow:
- **List-driven.** Every fix reads a class list from mod data (e.g. `DataMod\classes.txt`: name, art files, palette, dragon, base moveset, menu skin), never a hard-coded "class 6". Adding a class = a line of data plus its art.
- **Keyed by class number, not "the active class".** Lookups resolve per player, so different players' custom classes coexist.
- **Saves:** one sidecar file holds a record per extra class; the slot swap only concerns the local player's own class (see Save plan).
- **Online:** everyone in a room needs the same mod and the same class list; mismatches are refused, not desynced (extend the rebalance mod's modded-only rooms). How the class travels over the network is unverified, so check it early.
- **Known ceilings:** class numbers are mostly bytes (255); the item equip mask is 16 bits, so **16 classes total** without extra hooks (more needs wider masks in mod data); the select screen fits about 7 panels in one row, so more need a new layout (two rows, smaller panels or paging).

## The good news

- **Most lookups fall back safely.** About 127 code sites read six-entry per-class tables, and almost all are written as `class < 6 ? table[class] : table[0]`. A class number 6 gets the **Empress's** entry (name, art, text) instead of crashing. Each site can then be fixed on its own.
- **The game has grown before.** The select screen still contains the original four-class layout next to the six-class one, so the Shinobi/Witch DLC and the Oracle/Bandit updates were bolted on the same way.
- **Several limits are just "add an entry".** Class names, select text and art file names are short tables of string pointers that a hook can extend.
- **The equip mask** on items has 16 bits and uses 6, and the save's "class created" flags are a byte (8 bits), so both have room.

## Prototype status (2026-11-04)

`src/classes.cpp` + `mod\classes.csv`: class 6 (Empress moves, own body `pl6_cb00` and palette `pl6_pal`) **spawns and plays a quest, visible, status menu working**, via a test switch that turns the Empress into class 6 (saves redirected to `SystemData.bin.class-test`; the real save stayed byte-identical).

What it took:
- **117 table reads** of 36 read-only per-class tables repointed to 128-entry copies (`src/classes_sites.inc`, generated by `tools/re_gen_class_sites.py` from a disassembly: known tables, six-pointer tables, and six-string tables whose 7th entry doesn't continue the count). Includes the player type table, the per-class preload/setup functions (0x111A1A4/0x111A174), the EXP table (0x102E758, 25 reads), names, menus, story variants, dragon.
- **Palette pair cache** at 0x28ED298 (writable, filled at runtime, read as `[class*8]` in 0xD66730): {hash of palette file, hash of "<body>.osp"} per class; replaced with a 128-pair copy. **A palette's ID is hash("<sprite>.osp")** (pl0_cb00.osp, pl0_cw00.osp, pl5_pal.osp for the Bandit).
- Body/weapon file function 0xD79D80 and wrapper 0xD79E30 bounds raised.
- **Save support done:** the extra class's data swaps into class 0's byte ranges and lives in `SystemData.bin.classes`; the real save is written with the Empress's bytes (verified byte-identical). Needed the setup validator's limit raised (0xC928B2: 5 -> 127). Still redirected to `SystemData.bin.class-test` while the test switch is on.
- Still to cover: the dragon `.osp` cache at 0x28ED1E8 (read at 0xD71168), bounded sites that fall back to class 0 (names etc.), the select screen panel (the select and shop previews still show/expect the Empress: test-switch artefacts), online.

Debugging aid: `src/proxy.cpp` logs first-chance access violations with the exe address and return addresses.

## Save plan (recommended)

Constraints: the save file must stay readable by the unmodded game (players without the content mod, or with the mod removed), and must never hold a class-7 record where the game expects the Empress.

1. **Sidecar file.** Class 7's record (and anything else of its own) lives in a separate file next to the save, written by the content mod (e.g. `SystemData_class7.bin`, same encryption so it's tied to the account).
2. **Slot swap.** The game already sends class number 6 to record 0 at all 49 sites. When class 7 becomes the active class, the mod copies the Empress's record aside and puts class 7's record into record 0; when the player leaves class 7, it swaps back. No per-site hooks needed.
3. **Save-writer hook.** The game serializes the save into a buffer, checksums and encrypts it (~0xBD3F1F..0xBD40C1, cipher 0xE81590). One hook just before the checksum: write the stashed Empress record back into the buffer (so the file always has the real Empress) and write class 7's record to the sidecar. Autosaves use the same writer.
4. **Safety.** If the game crashes mid-session, nothing was written, so both files stay consistent. Removing the mod leaves a normal save and an unused sidecar.

Open points for implementation: the active class is the signed byte at contract header +3 (read at 0xD86FE7), so the swap can key off it; whether anything else per class lives outside the 0x34 record (sections A/B have more data, e.g. per-class tables behind offsets at B+0x1f4), and the select screen showing class 7's level from the sidecar.

## Suggested order

1. **Save data (8)**: decoded; plan above (sidecar + slot swap + one save-writer hook).
2. **Player object (1)**: found (0xDE7B90); hook it so extra classes spawn with a base moveset.
3. **Crash risks (1, 3, 5)**: the player-creation table read (0xDE7BA6), and the unbounded palette and text reads.
4. **Select screen (7, 10)**: add the panel, make it selectable and owned.
5. **Art and text (2, 4, 5, 6)**: point class 6 at its own files.
6. Then the class's own behavior (moves), story variants, voices.

Steps 1–5 would give a selectable seventh class that plays like an existing one with its own art, name and save data. That's the first milestone.
